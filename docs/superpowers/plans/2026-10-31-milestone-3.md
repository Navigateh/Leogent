# Leogent Milestone 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist every single-turn run in an append-only SQLite event log, restore session state from events, and add list/show/fork/resume CLI workflows.

**Architecture:** `SQLiteSessionStore` owns schema migrations, sessions, and ordered events. A small single-turn runner records user/model events around the existing Provider call; CLI commands are thin adapters over store operations. RunState is always reconstructed from immutable events.

**Tech Stack:** Python 3.11+, Pydantic 2, SQLite, Typer, pytest.

**Spec:** `docs/superpowers/specs/2026-10-28-leogent-phase1-design.md`

## Global Constraints

- Work only on `codex/milestone-3`; never modify or push `main`.
- Event payloads use JSON-compatible values.
- Events are append-only and use a positive, gap-free sequence per Session.
- Fork copies events into a new Session with new event IDs.
- RunState is reconstructed from events rather than stored as another source of truth.
- Milestone 3 remains a single-turn provider flow; tool execution stays in Milestone 4.
- Do not push the branch.
